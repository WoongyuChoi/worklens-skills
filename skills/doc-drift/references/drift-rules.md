# Factual drift review

## Choose the authority

A descriptive manual can be corrected to match verified behavior. A specification may instead expose an implementation defect. If authority, version or applicability is unclear, preserve both statements and ask for the missing decision only when needed.

## Evidence rows

Record document location and quote a short relevant claim, matched implementation path and symbol, verified behavior, disposition and proposed wording. Use these dispositions: 불일치, 확인 필요, 범위 내 모순 없음.

Check defaults, accepted parameters, validation activation, setup commands, file paths, constraints and supported modes. A default defined in one file may be overridden by a profile or caller. Follow only enough local configuration to establish the claim.

## Edits

For a check request, produce the mismatch table. For an update request, apply only supported documentation changes. Preserve source terminology, section order and links. Never adjust a requirement just to make tests or documentation appear consistent.

## Limits

Unsupported binary documents need an already installed reader or a text export. A read failure is 확인 못 함. Do not execute quoted setup commands or claim end-to-end behavior from static code alone. Do not broaden a sample check into all-system completeness.
