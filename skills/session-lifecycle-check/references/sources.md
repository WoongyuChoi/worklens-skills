# 세션 생명주기 조사 근거

조사 기준일: **2026-11-09**. 공식 자료의 검증 원리를 바탕으로 자체 작성한 스킬이다. 외부 제품 코드나 스킬을 복제하지 않았고 실행 중 자료를 다운로드하지 않는다. 제품명이나 CVE만으로 사내 시스템의 영향을 판정하지 않는다.

| 자료 | 공개·갱신일 | 확인 조건과 반영점 |
| --- | --- | --- |
| [Keycloak GHSA-xpwp-2pcm-8xq3](https://github.com/keycloak/keycloak/security/advisories/GHSA-xpwp-2pcm-8xq3) | 2026-09-16 공개 | stateless 모드와 MySQL/MariaDB의 행 수 의미 차이로 1회성 증표 재생 방지가 우회된 사례. 영향 `>=26.7.0, <26.7.4`, 수정 `26.7.4`. 소비 표시보다 두 번째 사용 결과를 확인한다. 다른 DB·모드로 일반화하지 않는다. |
| [Keycloak CVE-2026-18963 공식 이슈](https://github.com/keycloak/keycloak/issues/51833), [26.7.2 공식 릴리스](https://www.keycloak.org/2026/08/keycloak-2672-released) | 2026-08-19 공개·릴리스 | 복구의 이메일 검증이 강제되지 않은 사례이며 26.7.2에 수정이 기록됐다. 화면 단계와 서버가 확인한 증표를 분리한다. 댓글의 영향 버전표를 의존성 판정 근거로 사용하지 않는다. |
| [RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html), §§2.2.2, 4.14 | 2025-01 발행 — 기존 기준 | 공개 클라이언트의 refresh token에는 송신자 제약 또는 회전이 필요하다. 로그아웃·비밀번호 변경 시 refresh 자동 폐기는 MAY이며 모든 JWT의 즉시 무효화를 보편 정책으로 강제하지 않는다. |

합성 예제는 특정 제품의 CVE 재현물이 아니다. 실제 IdP, DB 드라이버, 클러스터, 사내 Agent 연결은 별도 증거가 필요하다. 날짜가 없는 일반 문서를 최신 사고인 것처럼 소개하지 않는다.
