설명용 · 로컬 이벤트
서버 요청과 실제 앱을 실행하지 않습니다. 이 파일에서 확인한 결과는 프로젝트의 React·HTTP·저장 처리 검증과 별개입니다.

1. 요청을 만들고 순서를 정하세요

빠르게 보려면 ‘A·B 예제 준비’ 후 ‘B 성공 → A 성공’을 누르세요. 두 요청은 서로 다른 조직을 조회합니다.

2. 원하는 요청부터 완료하세요

    아직 대기 중인 요청이 없습니다.

    이 도구가 적용한 규칙과 한계

    하나의 조회 패널에서 최신 요청만 유효하다는 정책입니다. 완료 시 요청의 세대 번호, 조직·기간 키, 화면 활성 상태가 모두 일치해야 데이터·오류·로딩을 갱신합니다. 같은 문맥의 재조회도 새 세대입니다.

    문맥만 바꾸거나 화면을 떠나면 기존 요청을 무효화합니다. 두 패널에 동일한 초기화 정책을 적용한 뒤 완료 처리만 비교합니다. 여러 독립 패널·페이지 누적·서버 저장에는 각 계약에 맞는 별도 정책이 필요합니다.

    서버 저장 취소·중복 저장 방지·실제 컴포넌트 생명주기는 검증하지 않습니다. 입력은 메모리에서만 다루며 새로고침하면 사라집니다. 최대 60개 요청과 200개 이벤트를 유지합니다.

    이벤트 기록

      실제 앱에서는 동일한 순서로 기존 시험 환경의 Promise를 직접 완료시켜 확인하세요. 이 도구의 통과가 앱의 통과를 의미하지 않습니다.
