# 신규 20개 사용 안내

작성일: 2026-11-03. **구현 완료 / 사내 반영·사내 Qwen 실행·실무 유용성 확인 전**입니다.

이번 팩은 현재 코드·설정·덤프·로그에서 확인할 수 있는 문제를 중심으로 구성했습니다. 모든 스킬에 좁은 호출 조건, 전문 참조와 구체적인 결과 양식 또는 예시가 들어 있습니다. 6개에는 브라우저에서 직접 열어 쓰는 HTML 도구도 있습니다.

## 어떤 파일을 받으면 되나요?

| 파일 | 용도 |
|---|---|
| worklens-skills-new-20-20261103.zip | 기존 20개를 이미 반입한 환경에 새 20개 추가 |
| worklens-skills-all-40-20261103.zip | 기존 20개와 신규 20개를 한 번에 보관·반입 |

두 파일의 신규 20개 내용은 같습니다. 사내에서 수정한 기존 스킬이 있으면 추가팩부터 사용하는 편이 교체 범위를 줄일 수 있습니다. 통합팩은 이전 개별 스킬을 자동 삭제·설치하지 않습니다.

압축을 풀고 `index.html`을 여세요. 카테고리·스킬 이름·요청 문장으로 검색하고 HTML 도구를 열 수 있습니다. `skills/스킬이름`을 폴더째 복사하며, 분류명 때문에 실제 설치 폴더를 한 단계 더 중첩하지 않습니다.

## HTML 6개는 무엇을 하나요?

### 한글·바이트 경계

`skills/encoding-boundary/assets/tool.html`

텍스트를 UTF-8로 인코딩하거나 원본 파일/16진수 바이트를 지정한 문자셋으로 디코딩합니다. UTF-16 단위·코드포인트·바이트 수를 구분하고, 바이트 제한에서 잘린 접두부를 확인합니다. 원본 바이트와 BOM을 보존합니다.

- 입력 최대 128 KiB, 문자 표는 앞 2000 코드포인트를 표시합니다.
- EUC-KR/MS949 **인코딩**과 손상된 원문의 자동 복원은 하지 않습니다. 디코딩 성공이 원본 문자셋의 증명도 아닙니다.
- 글자처럼 보이는 단위와 코드포인트 수가 같다고 가정하지 않습니다.

### 배치 일정

`skills/schedule-lens/assets/tool.html`

Spring 초 포함 6필드의 숫자·목록·범위·증분 부분집합을 계산합니다. 일과 요일을 동시에 제한한 식, L/W/#, 이름·매크로, 5·7필드 및 다른 방언은 거부합니다. 고정 UTC 오프셋만 지원하며 DST·휴일 캘린더·misfire·분산 락은 계산하지 않습니다.

- 최대 93일·20개 작업, 작업별 5000회·전체 10000회, 중첩 2000건입니다.
- 수행시간을 아는 두 실행은 `[시작, 종료)` 구간으로 비교합니다. 미상이거나 0초이면 동시 시작만 비교합니다.
- 조회 시작 전부터 실행 중이던 작업은 제외합니다. 상한 때문에 결과가 잘리면 중첩 판정도 불완전하다고 표시합니다.
- 실제 스케줄러 버전과 운영 실행 확인은 별도입니다.

### 스레드 덤프

`skills/thread-dump-lens/assets/tool.html`

전통적 HotSpot 플랫폼 스레드 텍스트 1~5개를 비교합니다. 명시된 intrinsic monitor의 소유·대기 순환과 시점별 동일 스택을 찾습니다. 원문 줄·락 ID·미확인 소유자를 함께 남깁니다.

- 덤프별 2 MiB 문자·40000줄·2000스레드입니다. 스택이 150프레임을 넘으면 동일 스택 요약에서 제외합니다.
- Object.wait가 놓은 모니터를 소유자로 처리하지 않습니다. WAITING이나 RUNNABLE 상태 하나로 서버 상태를 확정하지 않습니다.
- 가상 스레드 JSON·AQS/ReentrantLock 소유 관계는 자동 판정 범위 밖입니다. 프로세스 재시작과 덤프 시각은 별도 확인합니다.

### 비동기 응답 실험

`skills/async-state-guard/assets/race-lab.html`

A/B 요청을 시작한 뒤 성공·실패 응답 순서를 직접 바꿉니다. 같은 문맥 재조회, 문맥만 변경, 화면 종료와 복귀를 조작하며 보호 전후의 데이터·오류·로딩 상태를 비교합니다. 타이머나 서버를 사용하지 않는 설명용 실험입니다.

실제 React 컴포넌트를 마운트하거나 프로젝트 API를 호출하지 않습니다. 조회 응답 무시와 서버 저장 취소를 혼동하지 않도록 지침에 구분했습니다.

### 코드 경로 안내

`skills/code-path-tour/assets/tool.html`

스킬이 실제 소스에서 작성한 안내 JSON을 열어 단계 이동·검색·분기 탐색을 제공합니다. JSON과 자료를 내장한 단일 HTML을 저장할 수 있습니다. 파일·줄·호출 관계를 읽은 근거와 추론을 구분합니다.

- 일반 입력 2 MiB 이하, 1~100단계·500연결입니다. ID는 문자열로 보존합니다.
- 자료가 없는 단계는 파일·줄 번호를 만들지 않고 공백으로 표시합니다.
- 뷰어는 실제 저장소 파일 존재나 코드 실행을 검증하지 않습니다. 합성 예제는 합성으로 표시합니다.

### 장애 시간표

`skills/incident-evidence/assets/tool.html`

명시한 ISO 형식의 날짜·시각을 읽고 원문 파일·줄과 함께 정렬합니다. 오프셋이 없는 행은 사용자가 소스의 고정 오프셋을 지정하지 않는 한 미해결로 남깁니다. 스택의 여러 줄은 원문 범위를 유지합니다.

- 8개 소스·합계 2 MiB 문자·소스별 20000줄·시간 기록 10000건입니다.
- 요청 ID/문자열 필터와 JSON/CSV 저장이 있습니다. JSON에는 미해결 기록과 원문도 들어갑니다.
- 서버 시계 오차를 보정하거나 시간 순서를 인과 관계로 해석하지 않습니다. 복구 성공은 별도 근거를 확인합니다.

## 실제로 시험할 때의 기준

스킬마다 작은 실제 업무 한 건을 정해 아래 네 가지를 확인하면 개수보다 활용성을 평가하기 쉽습니다.

1. 긴 사전 설명 없이 필요한 파일에서 시작했는가?
2. 기본적인 설명을 넘어 문제 위치·경계·반례·수정안 또는 재사용할 결과가 남았는가?
3. 근거 없는 원인·실행 성공을 만들지 않았는가?
4. 기존 스킬과 결과가 겹치면 합치거나 제외할 수 있는가?

**좋은 결과의 예:** “XML 42줄의 collection은 ids인데 인터페이스의 실제 이름은 orderIds입니다. 같은 인터페이스의 단일 scalar 메서드는 정상일 수 있어 별도 오류로 분류하지 않았습니다. 프로젝트 실행은 하지 못했습니다.”

구현된 도구의 계산 검증과 사내 모델의 스킬 선택·지시 준수는 다른 확인입니다. [검증 기록](VALIDATION.md), [조사와 선정 근거](CANDIDATES-2026-11.md), [출처](SOURCES.md)를 함께 보세요.
