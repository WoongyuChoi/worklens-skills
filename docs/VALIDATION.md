## 로직 테스트의 주요 사례

- CSV의 인용된 쉼표, 여러 줄, 따옴표, 빈 필드, 중복 머리글
- 헤더 없는 CSV의 첫 레코드 보존
- TSV와 세미콜론 구분자
- 잘못된 CSV, 열 수 불일치, 빈 파일, 지원하지 않는 형식 거부
- JSON의 긴 숫자, 소수 표기, 앞자리 0, 중첩 값 보존
- JSON의 null, 비슷한 문자열, 누락 필드 구분
- 비정상 JSON 숫자 문법 거부
- XML DOCTYPE 거부
- 레코드 제한, 검색, 페이지당 표시 개수
- HTML처럼 보이는 입력을 코드로 삽입하지 않음
- 텍스트 도구의 기본 무변경 동작, 명시적 옵션 처리, 입력 변경 시 결과 무효화
- 화면 시안의 필수값, 중복값, 등록과 집계, 복합 필터와 초기화

## 개발 스킬 적용 예제

독립 에이전트에 검색 기능의 요구사항과 초기 소스만 있는 Git 없는 폴더를 제공했습니다.
짧은 요청은 “요청된 기능 개발하고 QA까지 해줘”였으며 스킬 경로를 함께 제공했습니다.
작업은 이 예제에서 순차로 제한했습니다.

검색어 공백과 대소문자, 담당자 검색, 상태 필터, 두 조건의 교집합, 입력 순서, 빈 값, 원본 비변경 등을 구현했습니다.
작성한 테스트 11개를 주 에이전트가 다시 실행해 통과를 확인했습니다.
이는 현재 실행 환경의 에이전트 적용 사례이며 **사내 Qwen 모델 평가나 실제 병렬 처리 성능 측정은 아닙니다.**

## 확인 못 한 것

- 실제 브라우저 렌더링, 키보드 포커스, 클립보드 권한, 다운로드와 반응형 배치
- 브라우저 DOMParser에 의한 일반 XML 표시와 레거시 문자 인코딩
- 사내 Qwen 3.8 기반 모델의 스킬 선택률과 지시 준수
- 설치된 사내 CLI 버전의 스킬 등록, 서브에이전트 호출, 동시 처리 속도

현재 검증 환경에는 실행 가능한 Chromium이 없었으며, 추가 확보 시도도 정상 다운로드로 이어지지 않았습니다.
따라서 Node VM 검증을 브라우저 실행 검증으로 표시하지 않았습니다.

## 재실행

스킬 사용자는 아래 개발용 도구가 필요하지 않습니다.
저장소 유지보수 환경에 Node.js가 있으면 다음 두 검증을 실행할 수 있습니다.

    node tests/validate.cjs
    node tests/logic-check.cjs

이미 설치된 Playwright와 Chromium이 있는 환경에는 브라우저 검증도 준비되어 있습니다.

    node tests/browser-check.cjs

기존 Chromium 경로를 지정해야 한다면 WORKLENS_CHROMIUM 환경 변수를 사용합니다.
스크린샷과 결과는 로컬 test-results 폴더에 생성되며 저장소 업로드 대상에서 제외됩니다.
브라우저 검증 스크립트는 준비됐지만 현재 환경에서는 브라우저 부재로 전체 실행되지 않았습니다.
