### 별도 세션에서 실제 요청 적용

작성자의 진단이나 예상 답을 주지 않고, 관련 SKILL과 합성 원자료를 읽어 실제 요청 결과물을 만들게 했습니다. 이는 현재 호스트의 에이전트 적용이며 사내 Qwen 평가가 아닙니다.

- **바이트·덤프·시간표·일정·코드 안내:** 5개 엔진 CLI 종료 코드 0, 별도 결과 검사 18개 통과. 5바이트 UTF-8 잘림, 두 모니터 순환, 3개 확정 시각과 1개 미해결 시각, 윤년의 60초 중첩, 합성 표시를 유지한 내장 HTML을 만들었습니다.
- **비동기 상태:** 제공한 실제 fixture 콜백으로 원본 결함 2건을 재현하고 수정 시나리오 12건과 보호 제거 감도 1건을 확인했습니다. React 마운트·브라우저는 실행하지 않았습니다.
- **키보드·포커스:** 원시 JSX를 읽어 초기 포커스·배경 격리·Escape·복귀의 빈틈을 찾고 수정 사본 및 수동 조작표를 만들었습니다. 실제 키 이동은 미확인입니다.
- **기존 동작 고정:** Java 원본에서 14개 출력/예외를 관측하고 리터럴 기준을 고정했습니다. 절삭→반올림 변이에서 expected=7, actual=8로 실패하고 원복 후 통과했습니다. 관측값을 업무 정책의 승인으로 확대하지 않았습니다.
- **assertion 검증력:** 길이만 확인한 원본 시험이 선행 0 손실·잘못된 이름·중복 ID의 3개 변이를 놓쳤습니다. 보강 assertion에서 해당 결함을 검출하고 매번 원복·재통과했습니다. 요구가 없는 반환 순서는 새로 고정하지 않았습니다.

- **개발 영역 8개:** API·Mapper·동일 버그·SQL·DDL·트랜잭션·배치·의존성의 원시 합성 fixture 각각에 소스 줄이 연결된 보고서를 만들었습니다. JSON alias와 실제 응답 이름, scalar MyBatis 정상 경로, 작은 테이블 FULL SCAN, catch 이후 rollback-only, 독립 트랜잭션 반영 등을 구분했습니다. DB·Spring·Gradle·JEUS 실행은 하지 않았습니다. 배치 중복은 별도 정수 산술 시뮬레이션으로만 검산했습니다.

총 17개 스킬에 독립된 실제 요청 적용을 수행했습니다. 나머지 설계 대안·업무 날짜·불변식은 지침/참조 검토와 해당하는 합성 예제 확인 범위이며, 모든 스킬이 모든 실제 업무에서 성공했다는 뜻은 아닙니다.

### 적용 중 발견해 보완한 점

- SQL 변경안의 “bind types 보존” 문구가 잘못된 바인드 타입 교정도 금지하는 것으로 읽힐 수 있어, 원래 타입을 증거로 기록하고 교정은 명시한 통제 변수로 검증하도록 고쳤습니다.
- 일정·코드 안내의 CLI 사용 방식이 문서만으로 충분히 드러나지 않아 파일 인자 방식과 명시한 실행 예를 추가했습니다. 이전 stdin/stdout도 유지합니다.
- 브라우저 없이도 이미 설치된 Node로 자료가 들어간 단일 코드 안내 HTML을 만들 수 있도록 별도 내보내기 명령을 추가하고 검증했습니다.
- 긴 스택을 일부만 캡처한 경우 동일한 전체 스택이라고 요약하지 않도록 제외하고, UI의 잘못된 UTF-8 오류와 오래된 결과 무효화를 확인했습니다.
- 신규 선택 CLI는 잘못된 UTF-8을 조용히 대체하거나 기존 결과 파일을 덮어쓰지 않습니다.

### 확인 범위와 남은 제한

- Node v24.22.1, 기존 OpenJDK 17.0.20을 사용했습니다. 날짜 경계·불변식·assertion의 JDK 단일 파일 합성 예제도 실행했습니다.
- **Chromium 실행파일이 없어 실제 브라우저 렌더링·파일 선택·다운로드 UI·모바일 폭·키보드 조작은 검증하지 못했습니다.** 최소 DOM/VM에서 Blob 내용과 이벤트를 확인한 것을 브라우저 시험으로 표현하지 않습니다.
- Spring/MyBatis/Oracle/Gradle/JEUS의 실제 프로젝트 구동, 운영 DB·배치 재시작, 가상 스레드 및 전체 cron 문법을 검증하지 않았습니다. 해당 스킬은 소스 근거와 실행 미확인 범위를 구분합니다.
- 실제 사내 Qwen의 자동 선택·도구 연결·지시 준수·반복 사용 효과는 확인 전입니다. 기존 사내 정리함 전체를 받은 것이 아니므로 중복 대조 범위는 이 저장소의 기존 20개입니다.

## 로직 테스트의 주요 사례

- CSV의 인용된 쉼표, 여러 줄, 따옴표, 빈 필드, 중복 머리글
- 헤더 없는 CSV의 첫 레코드 보존

- 잘못된 CSV, 열 수 불일치, 빈 파일, 지원하지 않는 형식 거부

- XML DOCTYPE 거부
- 레코드 제한, 검색, 페이지당 표시 개수
- HTML처럼 보이는 입력을 코드로 삽입하지 않음

- 설치된 사내 CLI 버전의 스킬 등록, 서브에이전트 호출, 동시 처리 속도

현재 검증 환경에는 실행 가능한 Chromium이 없었으며, 추가 확보 시도도 정상 다운로드로 이어지지 않았습니다.
따라서 Node VM 검증을 브라우저 실행 검증으로 표시하지 않았습니다.

## 재실행

스킬 사용자는 아래 개발용 도구가 필요하지 않습니다.
저장소 유지보수 환경에 Node.js가 있으면 다음 두 검증을 실행할 수 있습니다.

    node tests/validate.cjs
    node tests/logic-check.cjs

이미 설치된 Playwright와 Chromium이 있는 환경에는 브라우저 검증도 준비되어 있습니다.

    node tests/browser-check.cjs

기존 Chromium 경로를 지정해야 한다면 WORKLENS_CHROMIUM 환경 변수를 사용합니다.
스크린샷과 결과는 로컬 test-results 폴더에 생성되며 저장소 업로드 대상에서 제외됩니다.
브라우저 검증 스크립트는 준비됐지만 현재 환경에서는 브라우저 부재로 전체 실행되지 않았습니다.
