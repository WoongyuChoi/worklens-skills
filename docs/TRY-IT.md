# 짧게 요청해 보기

실제 기밀 데이터 없이 포함된 예시부터 시작할 수 있습니다.
스킬을 등록한 Qwen CLI를 프로젝트 폴더에서 실행하세요.
모델이 스킬을 선택하지 않으면 문장 앞에 스킬 이름을 덧붙입니다.

| 스킬 | 입력 상황 | 짧은 요청 | 확인할 결과 |
|---|---|---|---|
| file-explorer | tests/fixtures/sample.csv 경로 지정 | 이 파일 보기 좋게 | 앞자리 0, 쉼표, 여러 줄 값이 보존됨 |
| screen-prototype | 업무 목록 조회와 수정 이야기를 한 상태 | 이거 화면으로 | 검색, 수정, 검증이 동작하고 시안임을 표시 |
| task-to-tool | 중복 제거 작업의 입력과 결과를 확정한 상태 | 다음에도 쓰게 도구로 | 이미 정한 규칙을 다시 묻지 않고 실제 도구 생성 |
| visual-brief | 긴 작업 현황을 대화에 제공 | 팀장님께 보여주게 | 결론과 다음 행동이 한 화면에 들어옴 |
| diagram-maker | 승인/반려가 있는 업무 설명 제공 | 흐름 그려줘 | 분기와 복귀가 정확하고 추정 연결을 구분 |
| dev-conductor | 요청 문서와 소스가 있는 프로젝트 | 개발하고 QA까지 | 범위를 찾아 구현하고 실제 검증 수준을 보고 |
| qa-sweep | 방금 수정한 파일이 대화에 있음 | 마무리 검증해줘 | 확인 근거와 못 한 검증을 구분 |
| parallel-batch | 한 파일의 수정 방식을 확정함 | 나머지도 같은 방식으로 | 대상별 결과와 예외, 실제 병렬 여부 표시 |
| session-handoff | 작업을 진행한 상태 | 다음 세션에서 이어하게 | 인계 파일 생성, 이후 현재 파일을 다시 확인 |
| project-playbook | 프로젝트 규칙을 교정한 상태 | 다음부터 이렇게 | 규칙과 근거를 저장하고 기존 지침을 보존 |

## 정상적으로 멈춰야 하는 상황

- 대상 파일 후보가 여럿이면 하나를 선택하게 합니다.
- 이전 작업 기록이 없으면 기억하는 척하지 않습니다.
- 브라우저나 컴파일러가 없으면 실제 실행 검증을 했다고 쓰지 않습니다.
- 동일 이름의 메타 필드를 같은 데이터라고 단정하지 않습니다.
- HTML 파일에서 외부 리소스를 요청하지 않습니다.
- 파일 입력에 HTML 태그가 있어도 화면 코드로 실행하지 않습니다.

## 내부에서 품질을 비교하는 방법

같은 프로젝트의 짧은 요청 3~5개를 스킬 적용 전후의 새 세션에서 비교하세요.
결과 수정 횟수, 추가로 설명한 횟수, 끝까지 쓸 수 있는 결과 여부, 실제 소요 시간을 기록하면 됩니다.
모델이나 CLI 버전을 함께 적어 두면 이후 변경 효과를 비교하기 쉽습니다.
이 저장소의 로컬 템플릿 테스트를 사내 모델 성능 측정으로 해석하지 마세요.

## 2차 스킬 짧은 요청

필요한 대상 파일이 현재 대화 또는 프로젝트 안에 있다는 전제입니다. 경로 후보가 여러 개면 하나만 선택합니다.

| 요청 | 기대하는 결과 |
|---|---|
| 이 두 파일 안 맞는 것만 찾아줘 | 두 파일의 실제 처리 건수와 누락/중복/값 차이 |
| 이 입력 테스트할 데이터 만들어줘 | 이름 붙은 실제 입력 payload와 기대 결과, 서버 검증 여부 구분 |
| 이 화면 좀 덜 답답하게 다듬어줘 | 기존 스타일을 따르는 소스 수정과 실제 렌더링 확인 여부 |
| 이 로직 조건별로 표로 뽑아줘 | 우선순위와 예외를 보존한 표 및 코드 근거 |
| 개발이랑 운영 설정 다른 것만 보여줘 | 값이 기본 숨김 처리된 설정 차이와 미해결 변수 |
| 이 설명서 지금 코드랑 맞아? | 설명서의 불일치 및 수정 제안, 요구사항과 구현 권위 구분 |
| 이번 숫자 왜 달라졌는지 풀어줘 | 전체 합계와 증감이 정확히 일치하는 기여도 표 |
| 현업한테 확인받을 표 만들어줘 | 현업 조작 순서와 관찰 가능한 결과, 판정은 미실행 |
| 조합이 너무 많으니 줄여줘 | 제외/필수 조합을 반영한 조건 쌍 커버리지 검산 |
| 식별정보 가려서 공유본 만들어줘 | 같은 식별값의 일관된 토큰, 원문을 포함하지 않는 보고서 |

계산 도구 5개에는 `assets/example-request.json`과 HTML의 **합성 예시 넣기**가 있습니다. 실제 자료를 사용하기 전에 동작 형태를 확인할 수 있습니다. 예시 실행은 사내 실제 자료의 검증을 뜻하지 않습니다.
