# Worklens Skills

**짧은 요청에서 소스를 읽고, 근거와 확인 수준을 남기는 사내 Qwen용 기반 스킬 45개입니다.**

기존 40개에 보안 5개를 추가했습니다. 실행 지침은 영어, 사용자 결과와 예시는 한국어입니다. 소스 검토·HTML 사용에 인터넷·CDN·MCP·패키지 설치를 요구하지 않습니다. 실제 API 검증은 지정된 테스트 서비스와 이미 있는 HTTP/셸 기능을 사용합니다.

- **기존 20개:** 사내 반영 완료. 개별 유용성 평가와는 다릅니다.
- **3차 20개와 보안 5개:** 구현 완료. 사내 반영·사내 Qwen 실행·실무 효용은 확인 전입니다.
- **최근 피드백:** 반입한 스킬 중 실제 쓸 만한 것은 반 정도. 전문 업무와 명확한 결과가 있는 항목을 우선합니다.

## 보안 5개 — 무엇을 확인하나요?

다섯 스킬은 사내 정리함의 **`40_security` · 보안** 카테고리에 모읍니다.

| 우선 | 분류 | 스킬 | 짧은 요청 | 핵심 산출물 |
|---|---|---|---|---|
| 1 | 40_security | [API 인증·권한 검증](skills/api-authz-probe/SKILL.md) | 이 API가 익명이나 다른 조직 계정에도 열리는지 봐줘 | 소스 권한 행렬·실제 응답 비교·미검증 API |
| 2 | 40_security | [개인정보 로그 노출 점검](skills/privacy-log-audit/SKILL.md) | 개인정보가 로그에 찍히는 경로와 불필요한 출력을 찾아줘 | 필드부터 로그까지의 근거·출력 제외/최소화·재검증 |
| 3 | 40_security | [입력 경로 보안 검토](skills/source-sink-review/SKILL.md) | 외부 입력이 SQL·URL·파일 처리까지 도달하는지 봐줘 | 입력→검증→위험 처리·반증·국소 수정안 |
| 4 | 40_security | [라이브러리 취약점 영향 판정](skills/dependency-advisory-triage/SKILL.md) | 이 보안 권고가 우리 버전과 설정에 실제 해당하는지 봐줘 | 권고·실제 버전·기능·배포 조건 대조 |
| 선택 | 40_security | [에이전트 입력 경계 검증](skills/agent-boundary-check/SKILL.md) | Qwen이 문서나 API 응답의 가짜 지시를 따르는지 봐줘 | 제안·시도·차단·실행·효과를 구별한 trace 분석 |

추가 사례의 개인정보 로그 문제를 별도 스킬로 반영했습니다. 실제 로그를 외부로 가져올 필요 없이 소스와 필드명 목록으로 시작합니다. 기존 `sample-mask`와 달리 기록 경로와 출력 정책을 개선합니다.

API runner는 정확한 origin·경로·계정·합성 객체를 사용하고, 200만으로 취약점을 판정하지 않습니다. 기본 계획은 요청 0건입니다. 변경 요청·미확인 범위는 실행 결과와 구분합니다. 라이브러리 snapshot은 **6건의 선별 예제**이며 전체 CVE DB나 자동 최신 업데이트가 아닙니다.

각 보안 스킬에는 같은 형식의 **오프라인 HTML 보고서 뷰어**를 독립적으로 넣었습니다. JSON 선택, 검색·판정 필터, 근거 경로 SVG, 전체 coverage, 수정·재검증, 인쇄를 제공합니다. [보고서 형식](docs/SECURITY-REPORT-FORMAT.md)

## 폐쇄망에 가져가기

1. 제공된 **보안 5개 추가팩** 또는 **전체 45개 통합팩**을 반입하고 압축을 완전히 풉니다. GitHub에서는 **Code → Download ZIP**으로 전체 저장소도 받을 수 있습니다.
2. `index.html`을 열어 이름·요청·카테고리로 찾습니다. GitHub의 HTML 소스 화면은 실행 화면이 아닙니다.
3. 필요한 `skills/스킬이름`을 **폴더째** 사내 Qwen의 스킬 위치에 복사합니다. SKILL.md만 복사하면 참조 문서·실행 자산이 빠집니다.

| 적용 범위 | 일반적인 위치 |
|---|---|
| Windows 사용자 | `%USERPROFILE%\.qwen\skills\스킬이름\SKILL.md` |
| Linux 사용자 | `~/.qwen/skills/스킬이름/SKILL.md` |
| 현재 프로젝트 | `프로젝트/.qwen/skills/스킬이름/SKILL.md` |

현재 사내 CLI의 등록 방식을 우선합니다. `/skills`를 지원하면 등록을 확인하고, 자동 선택이 불안정하면 스킬 이름을 함께 요청하세요. 예: “privacy-log-audit 스킬로 이 모듈을 봐줘”. `agents/openai.yaml`은 호환용 메타데이터이며 Qwen 사용의 필수 조건은 아닙니다.

기존 스킬을 자체 수정했다면 사본을 보관한 뒤 교체 범위를 정합니다. 카테고리는 찾아보기용이며 실제 폴더를 `skills/20_dev/...`처럼 옮기지 않습니다.

## 기존 개발·문서 스킬

[3차 20개 사용 안내](docs/BATCH3-GUIDE.md)에는 Mapper·트랜잭션·배치 재시작·API 변경·날짜 경계 등의 요청과 도구 범위가 있습니다. [기존 사용 시나리오](docs/TRY-IT.md)도 함께 참고하세요.

전체 HTML 자산은 20개입니다. 기존 15개와 보안 공통 뷰어의 독립 복사본 5개를 뜻하며, 서로 다른 도구가 20종이라는 뜻은 아닙니다.

## 확인한 범위

구조·참조 파일, 표준 라이브러리 보조도구, 로컬 HTTP의 취약/수정 사례, 합성 코드·trace·로그 및 보고서 생성을 검증했습니다. 결과와 재실행 방법은 [검증 기록](docs/VALIDATION.md)에 있습니다.

현재 검증 환경에는 Chromium 실행파일이 없어 실제 브라우저 렌더링·파일 선택·다운로드 UI는 검증하지 않았습니다. JavaScript/최소 DOM 검사와 실제 브라우저 검증을 구분합니다. 실제 사내 서비스 침투와 사내 Qwen의 자동 선택·도구 호출·실무 효용도 확인 전입니다.

- [출처와 독립 작성 범위](docs/SOURCES.md)
- [개발용 검사](tests/README.md)

공개 스킬 원문·외부 scanner·프레임워크를 그대로 반입한 패키지가 아닙니다. 공식 자료를 참고해 필요한 절차와 자산을 독립 작성했습니다. 스킬 자체가 호스트에 없는 실행·병렬·로그 도구를 추가하지 않습니다.
